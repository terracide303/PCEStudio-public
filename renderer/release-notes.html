Beta 1 · builds from Sunday 1 November 2026

Release notes

What changed in each build, newest first, in plain words. Each line says whether it was tested and how. Anything not listed under "works" is not finished. What comes next, and why, is on the roadmap. The honest list of gaps is in the beta guide.

Build 5 · Tuesday 3 November

Controllers

  • A real gamepad now works in the studio and on the toy page. The standard layout maps to the PC Engine pad: A and B are I and II, Back and Start are Select and Run, the d-pad and left stick are the four directions, and X and Y are the extra buttons of a 6-button pad. A second pad plays as player 2. A new CONTROLS drawer lists each pad, lights the buttons as you press them, and lets you remap a button by pressing the new one. The keyboard keeps working beside it. built and checked in the host harness; try it with your own pad and tell us what you see
  • Exported ROMs already read the real pad port (the same reading a console does); a pad-test program and a check in a second emulator are still to come.

Assembly

  • A project can now be an assembly project: write .s files in the studio and the browser assembles them with PCEAS.
  • Our own hardware include file (pce.inc) and a HuCard builder make a ROM from a program, with a first example program. checked in an emulator only; not yet on a real console, and Lua calling assembly is not built

ROM limits and Claude

  • The ROM check now reports a budget: the data bank, constants, functions, registers and every other limit the interpreter refuses, each with what is used, what is left and a percent. It shows in the studio's ROM CHECK drawer and in the MCP tool.
  • The guide Claude reads now carries rules so it does not build a game that cannot export: check the budget before and after every change, undo a change that turns it red, stop adding at 80 percent and say so, and offer a smaller version instead of building something that will not fit. tested: the numbers in the guide are checked against the code

Pages, fixes and support

  • A new Hardware tricks page with five runnable studio toys, and a Resources page.
  • CITY's parallax bands now loop instead of stopping.
  • A yellow "Support me" link sits in the site ribbon and the studio's top bar.
  • Notes on how this studio fits with Geargrafx and the other tools developers already use were added to the roadmap.

Build 4 · Monday night, 2 to 3 November

Sound

  • In the studio, sfx() was silent unless music() had played first. The studio now sets the PSG's main volume itself, so a toy that only calls sfx() is heard. tested: the host harness checks the register writes
  • In exported ROMs, an effect's pitch lost the low byte of its value, so every sfx() pitch was wrong. That is fixed in the interpreter and the committed ROM image was rebuilt. tested: register-write comparison, and a Mednafen recording

Assembly, first steps

  • The PCEAS assembler (version 3.23) now runs in the browser as WebAssembly, with a wrapper and a check that compares its output with the command-line build. a proof only: it is not part of a project yet
  • The design note for assembly next to a Lua toy is written: where the routines live in the ROM, how Lua calls them, and the measured size budgets (docs/ASM.md). No code yet.

Planning and documents

  • A survey of existing trackers for the studio's own tracker (docs/TRACKER-SURVEY.md).
  • This page, the roadmap, the credits, the beta guide and the README were brought up to date.

Build 3 · Monday 2 November

Sound in exported ROMs, first half

  • The interpreter ROM now carries the HuTrack sound engine, so a ROM can play note(), sfx(), release() and music(). The interpreter image grew from 16 KiB to 32 KiB. tested on the host harness; its ROM checks still pass
  • The build now checks the memory budgets (zero page and stack) and fails if the engine breaks them.
  • not yet At this build the sound had only been checked on the host harness: not heard in Mednafen, and the trace test not written. Measured later on 2 November: the trace test is green, and the committed image's Mednafen recordings are audible — note() at 261/330/392/523 Hz and sfx() at 559 then 131 Hz, the pitches the studio writes. Music data in ROMs is still the next step: the ROM's song table has no song data yet, so a song plays in the studio but not in the exported ROM.

Export of the example games

  • DUSK RUN: the interpreter can now load its program (it used to refuse it, leaving a black screen). Its VRAM, colours and sprites are byte-equal to the browser's at frame 3, and its displayed picture now matches the browser's as well: the line chain is re-armed on every display frame and each line's write lands inside the blank. built; its picture is the browser's
  • TOWER still does not export: its bytecode (8,524 bytes) is larger than the 8 KiB data bank.
  • The test and build tools now find their programs after the work drive was renamed.

Site and repository

  • This release notes page.
  • The public repository and the site no longer carry a personal name; the documents say "the maintainer".

Build 2 · Sunday 1 November, evening

Connect Claude

  • Connect Claude button in the top bar; the AGENT panel shows live and the button reads Claude connected while a Claude Code session is linked to your tab. Claude can write, run, look at, check and export a toy in the tab you have open. tested end to end by a person with Claude Code
  • The relay that joins Claude Code to your tab runs on Cloudflare. A bug is fixed where the first call after the relay slept said "no tab" until the tab's next ping.
  • The old Download for Claude button is now a link in the AGENT panel for people without Claude Code.

Write for the ROM

  • While you write, the studio now tells you what an exported ROM can and cannot run (ROM check), also as the rom_check tool for Claude. tested; 315 MCP checks
  • The Claude Code tool source_add now records a picture's source, so the ASSETS panel lists it.

Site

  • A "not working yet" banner, a Connect Claude section and new rows in the beta guide, and an automatic redirect from http to https.

Build 1 · Sunday 1 November, morning

Export to a real ROM

  • PLATFORMER exports and runs in Mednafen at 30 Hz (24,576 bytes). It is the first game that does. tested in Mednafen; not on real hardware
  • The ROM now carries: calls with 5 to 8 arguments, the pad keys, the sprite table (sat), logical not, and sprite(i, spec) when the slot and fields are constants. Each has a ROM test that compares Mednafen's picture with the browser's.
  • The frame budget is now judged on a toy's steady state, not its first frame.
  • A measured table of how fast and how large each example game is as a ROM: docs/ROM_SPEED.md.

Sound plan

  • A measured design for sound in the ROM (docs/ROM-SOUND.md), both compilers learned note, sfx, release and music, and the SEQUENCER song and the 15 built-in instruments exist as HuTrack data (494 checks). the ROM cannot play them yet

Still not working

  • No ROM has run on a real PC Engine or a flash cart yet.
  • STARFALL does not export (constant pool and sprite specs); NOVA TIDE stops on its raster table; TOWER on its data size.
  • DUSK RUN exports and both its state and its displayed picture match the browser's. STARFALL exports and draws; its closest browser frame is 48 bytes off in the status bar's first tile row.
  • Notes and effects play in exported ROMs. Music data in ROMs, and a tracker, are in progress.
  • Planned, not built: the Lua-to-console compiler, the assembly chain, and opening an existing ROM in the studio.
  • Export error reports and a developer export (source out) are planned.

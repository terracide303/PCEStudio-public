Beta 1 · planned work, not promises

Roadmap

PCEStudio should be somewhere you can make a real PC Engine game, whether you write Lua, ask an AI, or program the chip in assembly. This is what we plan to build, and the reason for each part. Dates are not promised. What is already finished is on the release notes.

How to read the state column. works is built and tested. in progress is being built now. planned is decided but not started.

1. Games that really export

A studio is only as good as what you can play outside it. Today one game exports to a ROM, and nothing has run on a real console.

FeatureWhy we want itState
The five example games exportThey are the test of every limit in the exporter. Each refusal teaches us what is missing.in progress
Bigger games (bank switching, the larger mapper)The interpreter ROM has one 8 KiB data bank. Real games are larger.planned
A compiler from Lua to console codeInstead of an interpreter in the ROM, the studio would translate a game once into HuC6280 machine code. That is how games reach 60 Hz and fit in real cartridges, and it is what ppu.toys does for the SNES.planned
Faster outputGames run at 30 Hz through the interpreter. A direct code generator would reach 60 Hz.planned
Save data (backup RAM)Many games need to remember progress.planned
A test on real hardwareNothing is proven until a console or a flash cart runs it.planned

2. Sound and music

A game without sound is half a game, and a song should sound the same in the studio and in the ROM.

FeatureWhy we want itState
Sound engine inside the exported ROMThe ROM can play notes and effects through the HuTrack engine. The first half is built.in progress
Music data in ROMsThe SEQUENCER song and the built-in instruments, as HuTrack data.in progress
A full trackerPattern grid, instruments and waves, built on the same data the ROM plays. Dropping a .dmf file becomes one way to load a song into it.planned

3. Assembly for serious developers

Many PC Engine developers write assembly. They need no interpreter, no size limit and full control.

FeatureWhy we want itState
The assembler in your browserPCEAS compiled to WebAssembly, so .s files assemble on the page.in progress
Assembly projects and a HuCard builderWrite a whole game in assembly with our register include file, and build a .pce.planned
A HuC6280 CPU in the studioRun any program live next to the chip panels, instead of only toys.planned
Open an existing ROM in the studioDrop in a .pce you made (or own) to look inside it: its picture, palettes, sprites and sound, and to step through its code. Good for checking your own builds and learning from your own homebrew.planned
A profiler: CPU cost per scanline and per frameShow how much of each frame your main loop and interrupt handlers use. This is a gap in today's debuggers.planned
A live map of every ROM bankSee what is in each bank, how full it is and what moved after the last build. Squeezing out the last bytes is a long-running headache.planned
Symbol files other emulators loadWrite .sym files so Geargrafx and Mednafen show your labels. We aim to work with the tools you already use, not replace them.planned
Compression with the trade-off shownShow each asset's size saving and decompression time with ZX0.planned
A source folder for HuCC and PCEAS usersExport a project as plain files with a Makefile, so you can build it with your own toolchain.planned
Send a build to a flash cartResearch first: what a browser can do with a Turbo EverDrive or a programmable HuCard.planned
Run panel and debuggerStep, registers, memory, disassembly and breakpoints. Opening any .pce falls out of it.planned
Lua toys that call assembly routinesFast inner loops in assembly, the rest in Lua.planned
Take the project out as sourceA plain folder with the assembly, assets and a build script, so nobody is locked in.planned

4. Working with an AI

Making a game by talking to an assistant should work, and its output should be checkable.

FeatureWhy we want itState
Connect Claude, live in the tabClaude writes, runs, looks at and exports a toy in your open tab.works
Helpers so Claude does not rewrite convertersSprites from pixel grids, sound effect presets, music writing.planned
Export error reportsWhen an export fails, the error message and code line are sent so we can fix what blocks real games. No code or art is sent.planned

5. Art, tools and formats

Developers already use tools they like. We should read their files, not replace them.

FeatureWhy we want itState
Tiled maps, Aseprite filesThe common formats for maps and sprites.planned
Sprite sheets ripped from your own ROMA second emulator (Mesen 2) gives an independent picture to test against.planned
A project as a folder, a command-line buildWorks with git and automated builds.planned

6. Sharing

People should be able to show what they made.

FeatureWhy we want itState
Share a toy by linkA page for a toy that anyone can open and play.planned
Accounts and cloud saveOnly if it can be done with little data and clear privacy.planned

What we will not build

CD-ROM, Arcade Card and SuperGrafx support are not planned. Art from commercial games is never shipped with the studio, and sprite ripping is only for your own ROMs and files.

Have an idea, or want something moved up? Tell us.

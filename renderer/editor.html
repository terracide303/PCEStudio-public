PCEStudio editor — tiles, palettes, the map, sprites and scanline effects

Palettes — click a swatch, then a colour from the 512

VCE colour table (512 × 9-bit)

A swatch is one of a palette's 16 colours. Colour 0 of every palette (dashed) is the shared backdrop: the VDC shows CRAM $000 for every colour-0 pixel whatever palette the cell names. The BAT's palette field is 4 bits, so there are 16 palettes and a 17th is refused; a palette has 16 colours and a 17th is refused.

Tile

Click or drag to paint with the selected colour number. A tile is 8×8 pixels, each a 4-bit colour number 0–15; the 17th colour is refused.

Background map (BAT, 32×32 tiles)


The line at row 224 is the bottom of the 256×224 view; rows below it exist in the BAT and are not displayed at BYR = 0.

Sprite palettes — 16 × 16, CRAM $100–$1FF

Click a swatch, then a colour from the 512 above. A sprite pixel of colour 0 is transparent; entry 0 is the transparent entry and is never shown on a sprite (CRAM $100 is the background-off fill). A 17th colour in a sprite palette is refused.

Sprite pattern

Paint with the selected sprite-palette colour number (entry 0 is transparent). The sizes are the VDC's CGX/CGY: 16 or 32 wide, 16/32/64 tall; any other size is refused. Patterns are packed into VRAM cells after the tiles; one that would reach the SAT at $7F00 is refused.

Sprites — up to 64 in the SAT

X Y pattern palette

The VDC collects 16 strips of 16 px (256 px) a line in SAT order; sprites past that are dropped, and the budget shows the keeps and drops exactly as the renderer draws them. Lower SAT index wins an overlap; priority sets SPBG (shown over an opaque background).

Scanline effects — the #15 raster table

Each effect writes #15's raster table: the gradient one palette entry per line between two VCE colours, the wobble BXR per line from a sine (amplitude in pixels, period in lines, speed in lines per frame), each band its own BXR speed in pixels per frame. The preview is pce-bg.js/pce-sprites.js rendering that table — nothing is drawn separately. One VDW line carries one entry, so overlapping bands are refused; a line outside the 224-line display and a register value past its width are refused too. The .pce export still writes the static picture: the viewer runs the raster table in #16, so the effects are preview-only until then.

Preview — the VDC model (256×224)

The model's panels — the same state the preview draws

Every number below is read from the objects the renderer is given — vram, cram, sat, regs and the #15 raster table — not from a second copy of the picture. Click the preview to follow a pixel: the layer that won, its BAT entry/tile or sprite, the colour index, and the register values on that line.

VDC registers — all 20 (R00–R13)

The register file for the followed line. CR, RCR, BXR and BYR change per scanline when the raster table writes them (a * marks a line the table writes); the rest are the picture's own values or the viewer ROM's fixed 256×224 constants (HSR/HDR/VPR/VDR/VCR/DCR/DVSSR — tools/viewer.asm). A "—" is a register a picture never sets.

VCE — 512 colours as 32 palettes of 16

Palettes 0–15 are the background BAT's 4-bit palette field; palettes 16–31 are the sprite palettes at CRAM $100–$1FF. Entry 0 of a background palette (dashed) is the shared backdrop. Each swatch's tooltip carries its CRAM address and 9-bit word; the table is the followed line's, so a raster gradient shows here.

VRAM map — 32768 words

Whole VRAM, then words 0–4095 expanded: the BAT, the tile and sprite-pattern copy regions, the SAT at $7F00 and what is free. The regions are toPicture()'s copy descriptors (or regions.json for a dump), the patterns the cells the SAT names.

SAT — 64 sprites

Every SAT entry: Y, X, pattern (word 2 >> 1), palette, CGX/CGY size, flips and SPBG. Cells are the 64-word VRAM cells the VDC reads for that sprite; empty entries are all-zero.
